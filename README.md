# 연금 상담 AI 에이전트

### 제10회 2026 미래에셋증권 AI Festival 연금 Agent 과제 출품작 (수상하지 못했습니다)

**근거 없는 답은 하지 않는 금융 상담 에이전트입니다.**

퇴직연금과 연금저축의 제도와 세제를 묻는 질문에 주최 측이 제공한 문서만 근거로 답하고 모든 답변에 근거 원문을 함께 보여 줍니다.

> ⚠️ 이 저장소에는 대회에서 제공한 원본 문서와 그 문서를 가공한 데이터가 포함되어 있지 않습니다. 원본 PDF와 변환한 Markdown과 청크와 지식 그래프 데이터와 평가 질문은 모두 제외했고 직접 작성한 소스코드와 온톨로지만 공개합니다.

&nbsp;

## 🎯 해결한 문제

금융 상담에서 그럴듯하게 틀린 답은 고객의 실제 손해로 이어집니다. 그래서 근거 문서를 찾지 못하면 답변을 보류하도록 설계했습니다.

그런데 실제로 질문해 보면 근거를 찾지 못했다며 답하지 못하는 경우가 많았습니다. 원인을 확인해 보니 답이 문서에 있는데도 검색이 찾지 못하는 것이었습니다. 사용자는 "중간에 돈을 빼면"처럼 일상 표현으로 묻지만 문서에는 "환매"나 "중도인출" 같은 전문 용어로 쓰여 있어 단어가 일치해야 찾는 키워드 검색으로는 근거를 놓쳤습니다.

그래서 문제를 **표현이 달라도 근거를 찾아내는 검색**과 **찾은 근거 밖의 말은 하지 못하게 하는 답변 구조**로 나눠 풀었습니다.

&nbsp;

## 🧹 데이터 구조화

원본 문서를 검색할 수 있는 형태로 바꾸는 단계마다 다른 도구를 썼습니다.

| 단계 | 사용한 것 | 하는 일 |
|---|---|---|
| 문서 변환 | Upstage Document Parse | 제도 문서 10건을 두 파싱 모드로 변환하고 결과를 비교해 Markdown으로 만듦 |
| 문서 변환 | 텍스트 추출과 페이지 대조 | 나머지 제도 문서 47건의 표와 다단 구조를 페이지 이미지와 대조해 바로잡음 |
| 문서 변환 | Docling | 펀드 투자설명서 100건을 Markdown으로 변환 |
| 그림 처리 | 캡션 보존 | 이미지는 지우고 그림 옆의 설명 문장만 남김 |
| 청킹 | 제목 경계 분할 | 제목 단위로 397개 청크를 만들고 표의 행 사이에서는 자르지 않음 |
| 표 구조화 | TableRow와 TableCell | 표 93개 476행을 셀 단위로 저장하고 각 행을 "열 제목: 값" 문장으로 바꿔 따로 검색 |
| 수치 처리 | 구간 파서 | 세와 년과 원과 % 같은 단위 값과 이상 미만 같은 범위를 구간으로 바꿔 표 조회에 사용 |
| 임베딩 | Qwen3 Embedding 0.6B | 청크를 Dense 벡터로 바꿔 Qdrant에 저장 |
| 희소 색인 | BM25 | 상품 코드와 수치처럼 정확한 표현을 찾는 색인 |
| 온톨로지 | OWL/RDF와 SHACL | 연금 제도와 계좌와 세금과 업무 사건의 개념과 관계를 정의 |
| 지식 그래프 | Neo4j | 원문 인용이 붙은 관계 3,647개를 그래프로 저장 |

## 🔍 하이브리드 검색

검색 방식마다 잘 찾는 질문이 다르다고 보고 세 가지 검색을 함께 씁니다.

| 검색 | 잘 찾는 것 |
|---|---|
| BM25 키워드 검색 | 상품 코드와 수치처럼 정확한 표현 |
| Dense 벡터 검색 | 표현은 달라도 뜻이 비슷한 문장 |
| Neo4j GraphRAG | 질문의 개념과 연결된 조건과 예외 |

세 검색은 점수 기준이 서로 달라 점수를 직접 비교하지 않습니다. 먼저 Qdrant 안에서 Dense와 BM25 결과를 순위 기반 융합(RRF)으로 합치고 그 결과를 GraphRAG 결과와 다시 RRF로 합칩니다.

| 방식 | 상위 5개 안에 정답 근거가 포함된 비율 |
|---|---:|
| 키워드 검색만 사용 | 26.7% (8/30) |
| 세 검색 결합 | **100% (30/30)** |

이 수치는 상품 문서 1건으로 만든 평가 질문 30개 기준입니다.

## ✅ 답변 검증

LLM이 인용문을 직접 쓰면 원문에 없는 문장을 만들어 낼 수 있습니다. 그래서 인용을 LLM에게 맡기지 않았습니다.

1. HyperCLOVA X는 근거로 쓸 원문 구간의 ID만 고릅니다.
2. 실제 인용문은 서버가 ID로 원문을 찾아 붙입니다.
3. 별도의 HyperCLOVA X 호출이 답변의 모든 사실을 원문과 대조합니다.
4. 검증에 실패하면 원인에 따라 답변 교정과 재검색과 역질문과 답변 보류 중 하나로 처리합니다.
